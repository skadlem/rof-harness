## P1 — envelope evidence offline (zero spend, shipped 2026-11-11)

`tools/` only. Corpus: the 99 event dumps and 97 workdirs used by
`research/accounting-recompute.md`, replaying that validated counter model (90/99 exact) rather
than rebuilding it. Per run: terminal reason, assistant-turn count, input and cache-read tokens on
the final settled turn, cumulative counters at the kill, cumulative dollars. Three questions: how
far from the context limit the kill was (dying at 30-40% of the window would make the envelope the
cap, not context); what `miss-plus-out` would have bought on the identical traces, by replaying the
counter shape within the same 300k allowance at the observed per-turn miss+out cost and asking how
many runs already had a declared `Done` or a passing check in hand; and whether anything was
converging, since a run flailing at the kill is evidence *against* the hypothesis. Non-goal: a
solve-rate gain — this only tests whether the +15-turns counterfactual survives per-turn cost.

Acceptance: a committed TSV/JSON artifact plus a five-line summary, regenerated by one script,
unknown usage staying unknown, never zero; no paid re-run to fill a gap (a dump without usage is a
named exclusion). Gate: the script reproduces the artifact byte-for-byte from a clean checkout.

### The decided arm (never launched)

Adapter support exists (`tools/harbor_rof.py:36,160` forwards `budget_shape`); no adapter work.
**DECIDED 2026-11-11 (owner-authorized review, `decision-2026-11-11-1134.md`): B, amended** —
not the review's `miss-plus-out` vs `gross` pair, not the 2026-practice band:

0. **Fidelity probe (first paid step).** One control-envelope run on one cell, confirming the
   verifier sees `/app` after the workspace-fidelity fix. ~$0.03-0.11. If not, bank the remainder:
   an unprobed re-run repeats the void at ~$1.5.
1. Treatment = **600k miss-plus-out / 120 steps / 240 actions** ("candidate amendment 3" from
   `research/dphn-cap-ab1.md`) with its own post-fix control — NOT the void 18's rows. 3 cells x 2
   reps, cells where a row token-halted with steps unspent.
2. Report halt reason per rep; gross tokens per run is the only real guard; spend cap $2.00. A
   `done` halt with unspent cap is "envelope not binding", never treatment failure.

Why not the alternatives: a 3M/250-step arm's $3 per-instance guard cannot fire on the unpriced
vLLM endpoint and would be 96% of the budget; option C (a semantic-deliverable lever) was rejected
because scoping a lever to a named failing verifier test feeds hidden-verifier content into
runtime decisions.

Owner's call, not an implementer's: superseding `dphn-cap`'s registered KILL rule, and the README
"Void, re-measured pending" marking.

The original proposal was one treatment `budget_shape = miss-plus-out` against `gross`, everything
else frozen. **P1 changes this:** at 60 steps the step cap wins 105/135, so a shape-only arm would
report itself step-bound; the decided arm moves shape and steps together, which is two variables,
and that is the accepted cost.

Rules that make it attributable:

- Both arms pass explicit budget flags, so `budget_for` yields the same 3600s wall (FINDING 7;
  `crates/rof/src/cli.rs:1169-1182`). Never compare a flagged arm against a preset.
- The dollar cap is the binding guard in both arms; P0.1 must be merged first.
- Identical tasks, snapshot digests, model, endpoint, steps, actions.
- Rows carry `budget_shape` and never pool with the 99 pre-recipe dumps.
- Report first terminal reason and native reward per row; a `Done` or a verifier exit code is
  never a solve.
- Abort rule: if the summed per-run spend caps exceed the authorised remainder, the experiment
  does not launch.

**Blocked on owner decisions:** the ledger remainder ($0.300820902 against a $2.82 ceiling; the $4
figure is a per-instance envelope, not the campaign budget), which control recipe is current
(300k/60/120 or 1,200,000/120/240), and which tasks are shared with a rival.

**Acceptance:** the hypothesis is *supported* only if token-terminal runs fall **and** solves rise
in the paired comparison. Otherwise record `refuted` and go to P3's model-class test, not to a
bigger cap.
